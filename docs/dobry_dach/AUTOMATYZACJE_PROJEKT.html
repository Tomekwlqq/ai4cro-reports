A0 — Rejestr zapytań + follow-up

A0

Rejestr zapytań = baza klientów

🔴 blokowane
Pain: kontakt się urywa — nikt nie oddzwania, klient dzwoni 2. raz; zapytania „na tak" bez oferty giną (większość rynku).
Trigger: nowe zapytanie (telefon/mail) — ręczny wpis PH albo wykrycie w skrzynce.
Logika: 1) zapisz zapytanie do rejestru (Subiekt: kontrahent jednorazowy / Excel — do ustalenia) → 2) harmonogram follow-up: D+1 i D+3 przypomnienie oddzwonienia → 3) brak kontaktu po X dni → alert do biura.
Wyjście: wpis w bazie + mail przypomnienia („Zapytanie #X — oddzwonić do Kowalskiego").
ROI: odzyskane zapytania = nowe oferty; A0 mierzy % przepadających (dziś nieznany).
Blokery wiedzowe:
  • 00/1 — ile % zapytań realnie przepada przez brak oddzwonienia? (szacunek)
  • 00/2 — kto przyjmuje zapytania i wpisuje do bazy? (PH / biuro / oboje)
Zależne: A2 (oferta z ZK) — rejestr jest wejściem.

A1 — Scan projektu (Vision)

A1

Scan projektu → metryki

🔴 blokowane
Pain: projekt przychodzi w różnych formach; wymiary/powierzchnia/krycie przepisywane ręcznie do wyceny.
Trigger: projekt dotarł (PDF/zdjęcie/DWG/papier).
Logika: OCR/Vision → wymiary, powierzchnia dachu, krycie, typ pokrycia → prefill wyceny (metryki do ZK).
Wyjście: metryki + podgląd do wyceny.
ROI: oszczędność ~30–60 min na projekcie; zero błędów przepisywania.
Blokery wiedzowe:
  • 01/1 — rozkład form projektu w % (PDF/zdjęcie/DWG/papier)
  • 01/2 — gdzie ląduje projekt (Subiekt / dysk / segregator)
Warunek techniczny: cyfrowa forma projektu (bez niej nie ma A1).

A2 — Oferta z ZK + ślad negocjacji

A2

Oferta z pozycji starego ZK

🔴 blokowane
Pain: oferty „z głowy" poza systemem; 9 657 otwartych ZK = 529 mln pipeline, ale część bez śladu; negocjacje bez historii.
Trigger: akceptacja projektu / prośba o ofertę.
Logika: 1) pozycje ze starego ZK klienta (lub szablon) → 2) ceny z tw_Cena → 3) PDF oferty → 4) zapis jako nowy ZK; negocjacje = wersje oferty (historia).
Wyjście: oferta PDF + ślad w bazie (bramka: każda oferta w ZK).
ROI: oferta w minuty zamiast godzin; pełny ślad → A6/A7 mają dane.
Blokery wiedzowe:
  • 03/1 — jaki % ofert nie trafia do ZK (żyje w głowie/Excelu)?
  • 04/1 — czy negocjacje mają ślad (w ZK / mail / brak)?
Zależne: A0 (rejestr) + A3 (ceny/marża w ofercie).

A3 — Marża z bazy (algorytm Tomasza)

A3

Marża per dokument + flaga <5%

✅ odblokowane
Pain: 7% dokumentów TOWAR na minusie; marże 3–4% na dużych; wyceny „na oko".
Trigger: każda wycena / dokument sprzedaży.
Logika (algorytm Tomasza): marża = (Netto − Koszt) / Netto per dokument; RODZAJE: PNBM/inwestycja = 100% (koszt 0), TOWAR = realna, HURTOWA (do spółek) ~3–13%; flaga marży <5% przed wysyłką oferty.
Wyjście: alert „marża 3% — poniżej progu" przy wycenie.
ROI: koniec sprzedaży poniżej kosztu; świadome decyzje cenowe.
Status: algorytm wydobyty z pliku „sprzedaż 2026-05.xlsx" (301 dok., 2,66 mln netto).
🟡 Potwierdzenia (nie blokery):
  • 02/1 — czy każda wycena przechodzi przez arkusz kalkulacji?
  • 02/2 — skąd ceny w wycenie (tw_Cena / ręcznie / mieszane)?

A4 — Terminy: kalendarz + porównywarka

A4

Eventy terminów + porównywarka transportów

🔴 blokowane
Pain: terminy NIE żyją w bazie (dok_TerminRealizacji = data wystawienia, 100%); kalendarze per pojazd = jedyny rejestr; kto planuje — niejasne.
Trigger: akceptacja umowy → event; cron co 15 min → porównywarka.
Logika: 1) event z umowy (termin realizacji, ekipa) → kalendarz pojazdu (OAuth działa, read/write) → 2) przypomnienia ekipie (D-3, D-1) → 3) porównywarka: eventy („MR-ZK 95/MAG/07/2026") vs ZK w bazie — ZK bez transportu, konflikty pojazdów (2 eventy/dzień), ilości.
Wyjście: event + alerty („ZK #1234 bez transportu", „konflikt VW CRAFTER 14.08").
ROI: koniec zgadywania „czy każdy ZK ma transport"; postój ekipy = najdroższy koszt.
Blokery wiedzowe (6):
  • 05/1 — umowa z klientem przed startem — zawsze?
  • 07/1 — czy flagowanie (czerwona/żółta/zielona) realnie działa?
  • 08/1 — kto planuje transporty w kalendarzach?
  • 08/2 — czy każdy ZK dostaje transport?
  • 09/1 — jak logistyk dostaje zamówienie (mail / telefon)?
  • 09/2 — czy zdarza się zamówienie towaru bez ZK w systemie?

A5 — WZ → informacja do PH (postęp)

A5

Nowe WZ → wiadomość o postępie

🔴 blokowane
Pain: 62% WZ bez ZK — PH nie wie o wydaniach; % realizacji liczony z palca.
Trigger: nowe WZ (dok_Typ=11).
Logika: 1) WZ → powiąż z ZK → 2) policz postęp (wartość wyjechała / wartość ZK) → 3) wiadomość do PH („Dla ZK #1234 wyszło WZ #56, postęp 34%").
Wyjście: wiadomość (mail/WhatsApp — kanał do ustalenia).
ROI: PH na bieżąco; raport „w realizacji" = ile ma wyjechać vs wyjechało — mock gotowy (34%).
Blokery wiedzowe:
  • 10/1 — dlaczego WZ bywają bez ZK (celowe / błąd)?
  • 11/1 — jak PH dowiaduje się, że towar wyjechał (mail / telefon / nie)?
Zależne: A7 (różnice ZK vs WZ) czyta te same dane.

A6 — Raport PH (dzienny summary)

A6

Dzienny summary per PH

✅ odblokowane (działa end-to-end)
Pain: nikt nie widzi całości: nowe ZK, portfel, wydania, faktury, wpłaty — per PH.
Trigger: cron 7:00 (propozycja).
Logika: 1) nowe ZK (wczoraj) → 2) portfel otwarty (ZK 6/7) → 3) WZ i FS → 4) wpłaty → 5) per PH = kategoria dokumentu (dok_KatId) — przestawione z dok_PersonelId (wystawca ≠ prowadzący — naturalne) → 6) SMTP na odbiorców.
Wyjście: raport HTML (4 karty KPI) mailem — działa (wysyłka na 2 skrzynki potwierdzona).
ROI: 30 min dziennie na ręcznym składaniu; zero ślepej sprzedaży (zaległości 6,5 mln widoczne).
🟡 Czeka decyzje (nie wiedza):
  • godzina crona (propozycja 7:00) + odbiorcy (tomekw@ + tomekj@)
  • kopia bazy JAWNEJ — A6 na danych B2C (sprzedaż usług tam żyje)
Potwierdzenia:
  • 12/1 — kto pilnuje wpłat zaliczek?
  • 13/1 — kto dostaje dzienny raport PH?

A7 — Różnice ZK vs WZ + ślad zmian

A7

Rozjazdy przed finalizacją + komplet dokumentów

🔴 blokowane
Pain: finalizacja bez porównania ZK vs WZ; zmiany zakresu bez śladu (mail/telefon); archiwum dokumentów ręczne (teczka → Natalia).
Trigger: tygodniowo (pon. 7:30) + przy zmianie zakresu.
Logika: 1) porównaj pozycje ZK vs WZ per dokument (co zamówione vs co wyjechało) → 2) ślad zmian (zgłoszenie → wycena → akceptacja → aneks) → 3) lista dokumentów do kompletu (zamówienie, umowa, dokument 8%, FV, rozliczenie, FV dekarza).
Wyjście: raport rozjazdów + checklista kompletu.
ROI: zero niedomkniętych kontraktów; prowizje (Natalia) liczone z kompletów.
Blokery wiedzowe (4):
  • 06/1 — czy umowa z dekarzem na każdą budowę?
  • 14/1 — jak dziś wygląda zmiana zakresu (aneks / mail / bez śladu)?
  • 15/1 — czy rozliczacie ZK vs WZ przed zamknięciem?
  • 17/1 — czy archiwum (teczka → Natalia) realnie się składa?
