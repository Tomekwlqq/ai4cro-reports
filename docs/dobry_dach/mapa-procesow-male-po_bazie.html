0214 zasad budowy mapy

14 zasad, na których stoi ta mapa — każda węzeł i stan ZK im podlega.

  1. Warstwa AS-IS przed każdym TO-BE. Jeden akapit „jak dziś” z aktorem i czasem — dopiero potem automatyzacja.
  2. Jeden schemat opisu węzła. 14 pól — używane dla każdego węzła bez wyjątków.
  3. Sekwencja zamiast kart. Małe procesy jako jeden flow zależności: od zapytania klienta do FV finalnej.
  4. Aktor + urządzenie + soft + kanał obowiązkowe. Każde z 14 pól ma być wypełnione albo jawnie oznaczone jako nieznane.
  5. SLA z umowy wpięte w węzły. Protokół do 10. dnia, FV po zatwierdzeniu przez GW, dokumentacja w 4 egz. — terminy z umowy w odpowiednich węzłach.
  6. Pain pointy przypisane do węzłów. Z pptx, kwestionariusza i obserwacji — każdy ból ma adres.
  7. Efekt mierzony po wdrożeniu. Liczby efektu produkuje sam system po starcie — nie zbieramy ich przed budową.
  8. Statusy ZK jako maszyna stanów. Lista statusów, trigger wejścia, kto zmienia, co się odpala.
  9. Węzły wyjątków. Zmiana zakresu (14), zaległa płatność, reklamacja — kto, kiedy, eskalacja.
  10. Mapa dokumentów umowy. Który załącznik zasila który węzeł (WSW → oferta/finalizacja, Harmonogram → kalendarz, OWU → odbiory).
  11. Kanały komunikacji jako osobna warstwa. Mail/telefon/WhatsApp/SMS — kto → do kogo, per węzeł.
  12. Rozdział ról automatu. Co robi AI, co Python, co człowiek — w architekturze było, w krokach się mieszało.
  13. Status węzła. 🟥 nieznany / 🟨 założony / ✅ potwierdzony z klientem — mapa uczciwa co do wiedzy.
  14. Kolejność budowania od zależności. Nie od subiektywnego „największy efekt”, tylko od tego, które węzły odblokowują resztę.

07Architektura rozwiązania

Sześć klocków, jeden fundament: system magazynowy jako jedyne źródło prawdy. Agent nie duplikuje danych — odczytuje i przetwarza.

Subiekt GT (odczyt SQL)

Fundament — źródło ZK, WZ, cennika, płatności. POTWIERDZONE: odczyt przez SQL na lokalnej kopii bazy (Docker). Agent TYLKO odczytuje; zapis (statusy, dokumenty) przez Sferę.

Google Calendar API

Jeden kierunek na start: agent wpisuje eventy, nie czyta.

Mail (SMTP)

Wychodzące powiadomienia i raporty. Brak odbierania (na start). Raport on demand przez prosty formularz web.

Claude API

Vision (scan projektu), formatowanie raportów, weryfikacja umów. NIE LICZY — to robi Python.

Jedna aplikacja web

Użytkownik otwiera i wybiera klocek. Nie 6 osobnych narzędzi.

Lokalna kopia bazy (MSSQL w Dockerze)

Kopia produkcyjnej bazy Subiekta (pymssql, odczyt RO) + SQLite na historię ZK, klucze marż, log powiadomień. Praca bez ruszania produkcji.
