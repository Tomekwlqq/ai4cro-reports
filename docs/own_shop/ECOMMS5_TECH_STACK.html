3. Super opcje kontentowe — tu się wygrywa

High-ticket energetyka to zakup researchowany tygodniami. Klient nie „kupuje pompy", klient szuka odpowiedzi. Sklep, który jest jednocześnie najlepszym źródłem odpowiedzi w kategorii, przechwytuje decyzję zanim konkurencja pokaże cenę. Wszystko poniżej masz już metodologicznie gotowe — CS v3.1 dostarcza treść, stack ją tylko serwuje.

3.1 Konfigurator doboru — rdzeń przewagi (STATUS: „nikt na PL tego nie ma")

„Mam falownik X → które magazyny pasują" · „dobór mocy pompy do domu" · + cena + dotacja + montaż w jednym flow. Mechanika: engine CS generuje drzewo decyzyjne jako JSON → React island renderuje kroki → wynik to lista SKU z Medusy + CTA (koszyk lub wycena). Aktualizacja CS = aktualizacja konfiguratora, zero przepisywania UI.

3.2 Kalkulatory osadzone w treści

  • Kalkulator dotacji — KPO (min 2 kWh, do 50%/16k) vs Fundusz Modernizacyjny (min 10 kWh, 800 zł/kWh + EPS): wpisujesz pojemność → wychodzi realna dopłata i który program. Dane programów w jednym JSON — zmiana ustawy = edycja jednego pliku.
  • Kalkulator oszczędności pompy — metraż, ocieplenie, obecne źródło → szacunek rachunków (CEP z CS: EPBD 2028/2030/2040 jako trigger).
  • Porównywarka produktów — generowana z danych katalogu (API Medusy @ build), nie pisana ręcznie. Setki SKU = setki porównań bez pracy.

3.3 Content silnik: CS → strony

  • Discovery Questions z CS = FAQ i klastry poradników. Pole pytań już istnieje dla obu kategorii — każde pytanie to strona/sekcja MDX z odpowiedzią i schema FAQPage.
  • PDP wg standardu GEO — tytuły/bullets Tier-1, specyfikacje w tabelach, JSON-LD (Product, Offer, FAQPage, HowTo) — z automatu, bo strony generuje szablon, nie człowiek.
  • Huby kategorii (masz live: pompy, magazyny) wpinają się jako sekcja edukacyjna sklepu — z huba GEO robi się top-funnel sklepu.
  • SSG = każda strona pre-renderowana — AI search (i Google) widzi pełną treść bez JS. Twoja własna teza GEO, tu na własnym poligonie.

3.4 High-ticket = dwa flow, nie jeden

Koszyk to nie jedyna konwersja. Pompa z montażem = lead-flow: konfigurator → wycena → kontakt (model „warstwowy wybór montażu" z Idei — 3 poziomy). Magazyn/akcesoria = klasyczny checkout. Architektura musi mieć oba od dnia zero: Medusa robi checkout, formularz wyceny leci do prostego CRM (na start: Supabase tabela + Discord DM — infrastrukturę masz).

7. Integracje — integratorem jest AI

Zamiast middleware'ów (Zapier, Make, na start nawet Baselinker) każda integracja to skrypt w repo + cron/launchd + webhook + alert na Discord DM — wzorzec, który już masz przetestowany na GLOV (refresh + watchdog gdy dane starsze niż 2h, launchd przez python3 wprost). AI pisze skrypty, monitoruje logi, obsługuje wyjątki (nowy format feedu dostawcy, brak produktu w mapowaniu) i raportuje. Middleware kupuje się dopiero wtedy, gdy skrypt przestaje wystarczać — nie odwrotnie.

9. LLM Discovery — plan wygranej (Twój cel główny)

Fundament techniczny już sprzyja: crawlery AI (GPTBot, ClaudeBot, PerplexityBot) nie renderują JavaScriptu — czytają goły HTML. Astro SSG serwuje 100% treści w HTML, więc konkurencja na SPA-frontach jest niewidzialna tam, gdzie Ty jesteś cały.

  • Schema Tier-1 wszędzie (Product, Offer, FAQPage, HowTo, Organization): strony ze schematem cytowane 2.5–2.7× częściej (+157%); JSON-LD musi być 1:1 z HTML (data parity), inaczej sygnał nieufności.
  • Świeżość: content <3 mies = 3× częściej cytowany → cron odświeżania: ceny, dotacje, daty w poradnikach aktualizowane automatycznie (AI-integrator robi to za darmo, konkurencja ręcznie — czyli wcale).
  • Format pod cytowanie: 63% cytacji to listicles; pierwsze 30% tekstu zbiera 44% cytowań (odpowiedź z góry, nie po wstępie); tabele porównawcze + multi-modal = +156% selection rate. Standard szablonu MDX, nie dobra wola autora.
  • Pole pytań CS = mapa contentu: każde Discovery Question → strona z odpowiedzią w pierwszym akapicie + FAQPage schema. Ogrom × jakość × struktura — dokładnie to, co chcesz, tylko wykonalne masowo dzięki temu, że CMS-em jest AI.
  • Kanały danych: IndexNow → Bing → ChatGPT Search / Copilot / DuckDuckGo; feed do Microsoft Merchant = obecność w Copilot Checkout przy małej konkurencji; feed JSONL gotowy na EU-launch ChatGPT Shopping.
  • llms.txt: skip — Google oficjalnie "nie wspieramy i nie planujemy", 97% plików llms.txt ma zero ruchu (Ahrefs, 137K stron). Zgodne z naszym kanonem audytu. UCP Google: na razie US-only, monitorujemy.
