BUILD: Analityka live Bengshop (GA4 + Search Console + Clarity)

Projekt 20.10.2026 · status ✅ zbudowane 20.10 · wzór: GLOV Live2 (Projects/Shopify GLOV/glov_etl_live2.py → glov_live2.json → build_glov_live2.py → GLOV_Live2.html, publikacja refresh_glov.py, automat com.glov.refresh + com.glov.watchdog).

Cel

Jeden pulpit, który codziennie sam się odświeża i odpowiada na pytania, na które dziś odpowiadamy ręcznie: czy ruch i sprzedaż z Google rosną, które kanały sprzedają, jak zachowują się klientki na stronach i — najważniejsze przy przebudowie — czy zmiany w kategoriach nie zabrały ruchu (6 tygodni przed ↔ 6 tygodni po, próg −10%, ta sama reguła co w „Ruch z Google” i „Nawigacja sklepu”). Tylko GA4, Search Console i Clarity — bez Shopera i bez Meta.

🔴 Bramka wsadowa

  • Dostępy działają: GA4 (ADC, tools/bengshop_ga4_etl.py), Search Console (_shared/gsc_mcp.py), Clarity (token w .env, archiwum com.tomek.bengshop-clarity 07:10) — sprawdzone 13–19.10.
  • Decyzja Tomka przed publikacją: gdzie stoi pulpit. GLOV jest na publicznym GitHub Pages (ai4cro-reports). Dane klientki (sprzedaż) publicznie = wbrew zasadzie „wewnętrzne nigdy publicznie”. Rekomendacja: nasz serwer z logowaniem (ten sam, co edytor.ai4conversion.com / smk.ai4conversion.com). Alternatywa: GitHub Pages z nieindeksowanym adresem — szybciej, ale każdy z linkiem widzi sprzedaż.

Przepływ

launchd 07:40 → live_refresh.py → live_ga4.py --append · live_gsc.py --append · live_clarity.py → build_live.py → publikacja (po decyzji z bramki) → watchdog sprawdza kod wyjścia i datę pobrano.

Jak sprawdzę, że działa (liczby, nie „rc=0”)

  • W2: wrzesień 2026 = 287 kliknięć z Google dziennie i 94 z haseł bez nazwy sklepu — te same liczby co w data/google_2026.json.
  • W3: wrzesień 2026, Organic Search = 313 zamówień i 125,2 tys. zł — jak w data/ga4/kanaly_miesiecznie.json.
  • W5: lista produktów, próba z 13.10 = 26,4% szybkich powrotów — jak w data/sciezki/nawigacja.json.
  • W6: wyłączam ręcznie jedno źródło → na stronie znacznik „nieaktualne” i kod wyjścia ≠ 0 (lekcja GLOV: cichy fallback ukrywał awarię 24 dni).
  • tools/straznik_spojnosci.py przechodzi, strona na 390 px bez poziomego przewijania.

Czego nie jestem pewien

  • Gdzie publikować (bramka wyżej).
  • Czy Search Console API wytrzyma dzienne pobieranie dzień × adres bez limitu (przy ~4 tys. adresów — powinno; sprawdzę na pierwszym przebiegu).
  • Czy klientka ma zobaczyć cały pulpit, czy tylko W2–W4.

Kroki

  • K0 · W2 „Google tydzień po tygodniu” od pobrania do strony, lokalnie, pokazane Tomkowi
  • K1 · W3 sprzedaż według kanałów + W1 dziś/wczoraj
